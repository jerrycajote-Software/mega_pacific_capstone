# ADR-001: Use PostgreSQL as Primary Database

## Context
The Mega Pacific roofing system requires a reliable database capable of handling transactional order processing, strict foreign key constraints (e.g. products, variants, orders, order items), multi-table joins, and structured JSON arrays for multi-image galleries.

## Decision
We choose **PostgreSQL** as the relational database engine.

## Rationale
- Strong ACID compliance for critical order processing and financial tracking.
- Native support for array types (`String[]`) used in product multi-image URLs and review attachments.
- High performance for complex join queries across users, orders, items, and inventory logs.
- Native integration with Prisma ORM.

## Alternatives Considered
- **MySQL**: Good performance, but weaker native array support compared to Postgres.
- **MongoDB**: Schema flexibility is useful, but lack of strict multi-table relational integrity poses risks for financial order items and inventory counts.

## Status
**Accepted**
