# ADR-004: Use Express.js for REST API Server

## Context
The backend API requires route modularity, middleware support (JWT verification, role guards), WebSocket attachment for Socket.IO, and integration with Node.js email utilities.

## Decision
We select **Express.js v5** as the REST web framework.

## Rationale
- Minimalist, battle-tested framework with extensive ecosystem middleware (CORS, body-parser, JWT).
- Seamless integration with HTTP server and Socket.IO for real-time WebSocket rooms.
- Modular routing structure allows clear separation by role (`/api/admin`, `/api/customer`, `/api/sales`).

## Alternatives Considered
- **NestJS**: Highly structured, but higher initial boilerplate for a capstone timeframe.
- **Koa / Fastify**: Performance advantages, but Express has wider team familiarity and middleware compatibility.

## Status
**Accepted**
